Reconstruct a stable answer without changing its units

We have sparse and noisy measurements, distributed over surface positions, directions, and time. The remaining task is not “blur the image until it looks good.” It is to reconstruct an incoming field at each visible receiver, integrate it against that receiver's scattering response, and reuse only history that still describes the same surface and illumination.

Integrate the directional field

A diffuse surface needs irradiance \(E(n)=\int L_i(\omega)\max(0,n\cdot\omega)d\sigma\). This is a convolution with a broad cosine kernel, so it discards much of the high-frequency directional detail needed by a mirror. That observation makes low-order directional bases useful for diffuse lighting.

Spherical harmonics (SH) are an orthonormal basis of functions on the sphere, analogous to Fourier modes on a circle. A coefficient is an integral of the function times one basis function. The constant basis term carries the mean, with the normalization made explicit below; higher bands record increasingly fine directional variation. Three bands contain nine coefficients. Cosine convolution multiplies the first three bands by \(A_0=\pi\), \(A_1=2\pi/3\), and \(A_2=\pi/4\). Truncating there is an approximation, particularly for sharp occlusion and narrow light sources.

Normalization must match the stored representation. In the inspected screen-probe filtering path, the stored radiance SH is formed as an average over the equal-area sphere samples:

\[ s_{lm}\approx\frac1M\sum_{j=1}^{M}L_jY_{lm}(\omega_j),\qquad E(n)\approx4\pi\sum_{l=0}^{2}\sum_{m=-l}^{l}A_l s_{lm}Y_{lm}(n). \]

The factor 4π converts a sphere average into an integral. It must appear exactly once. The default irradiance storage path preintegrates the result into a 6×6 equal-area directional probe with a border (the engine names this format OCT); the SH3 storage path retains the coefficients and applies the factor at consumption. SH3 can be selected explicitly and is also forced when the configured short-range bent-normal AO path applies during integration. The card-radiosity SH path uses a different, PDF-weighted hemisphere projection with four coefficients. Its measure is different, so it must not inherit the screen-probe factor blindly.

A normalization test. For constant radiance L₀, only the constant SH coefficient is nonzero in the exact projection. Since \(Y_{00}=1/\sqrt{4\pi}\), the stored average coefficient is \(s_{00}=L_0/\sqrt{4\pi}\). Substitution gives \(E=4\pi\,\pi\,L_0/(4\pi)=\pi L_0\), exactly the hemisphere integral. Omitting 4π gives L₀/4 instead. This is a deterministic scale error, not noise.

Give those numbers a shape. At a captured probe position, evaluate the reconstructed unit-albedo diffuse response for many hypothetical receiver normals. Draw each normal as a direction from the probe and use the response magnitude as the distance along it. The resulting lobe is a graph of a function, placed in the scene where that function was measured. It is not a solid object, a traced ray bundle, or a volume occupied by light. A long upward lobe means a surface with an upward normal would receive more reconstructed diffuse illumination there. Its orientation can be compared with Sponza's opening; its value at the actual receiver normal can be compared with the integrated buffer.

For a temporal comparison, retain the same units, angular basis, exposure conversion, radius scale, and color mapping. Rescaling each lobe to its own maximum would make a fourfold drop in illumination disappear from the picture. Low-order reconstruction can also produce negative lobes near sharp changes. If the display clips them to zero, keep the signed coefficients and report that clipping; the display is not the stored representation. A changing lobe at a fixed position describes a changing estimated field. A lobe that jumps to another surface after camera motion instead needs a new geometric correspondence before its coefficients can be compared.

Separate normalization error from quadrature error. The decoder evaluates the constant-field test above with the analytic constant coefficient and obtains D=1 within 1.5×10−6 over 256 test normals. Projecting that same synthetic constant field through the actual 8×8 direction layout leaves small higher-band residuals; the worst deviation becomes about 2.05%. The first test checks the factor 4π and the Lambert factor. The second exposes the finite directional quadrature. Both are decoder tests with a declared synthetic input, not claims that the captured atrium has constant illumination.

The screen-probe diffuse output is the unit-albedo diffuse response, \(D=E/\pi\), multiplied by the view pre-exposure. Composition later multiplies D by the visible receiver's diffuse color. The receiver albedo and 1/π must each be applied exactly once. By contrast, the Surface Cache's final-lighting combine has already multiplied secondary direct-plus-indirect irradiance by the secondary surface's effective albedo/π and added emission. Its separate direct and indirect irradiance atlases remain unweighted by that albedo. Those two material interactions belong to different path vertices.

Interpolate only between compatible surfaces

Choose nearby probe candidates through the screen/adaptive-probe maps. Compute geometric weights using position, depth, and normal compatibility. Normalize accepted weights. If all candidates are rejected, use an explicit fallback rather than dividing by a tiny denominator and amplifying noise. A screen-space neighbor across a silhouette can be metres away in world space; pixel distance alone is not a transport relationship.

Spatial filtering of probe radiance also needs geometric checks. A ray hit distance helps distinguish an observed nearby wall from distant illumination. Position and angular thresholds limit mixing between incompatible observations. Several small filter passes can be cheaper than one large kernel, but their combined footprint still smooths the field. The output should be inspected at contacts and thin columns, not only on a large flat floor.

History is a previous measurement, not free ground truth

For a moving camera, the previous value at the same screen coordinate usually belongs to another world point. Reproject the current receiver into the previous frame using transforms and motion. Gather neighboring history taps, then validate each tap against depth, normal, material classification, and availability. Exclude invalid taps and renormalize. Occlusion changes create disocclusions: a newly visible surface has no valid previous observation, even when a nearby color looks plausible.

For valid history, a simplified blend is \(H_t=(1-a_t)H_{t-1}^{\rm reprojected}+a_t C_t\). A running-average weight \(a_t=1/(N+1)\) reduces the influence of each new noisy estimate as N grows. Capping N bounds the latency. Fast-update flags, neighborhood clamps, invalid-current-sample handling, and rejection can alter this rule in the actual shader. The final per-pixel temporal accumulation follows integration; there are also separate histories used earlier for probe radiance and sampling guidance. They are not one interchangeable “temporal buffer.”

If history stores view-pre-exposed lighting, it also needs the ratio of current and previous pre-exposure. Reprojection can identify the correct point yet still produce a brightness jump if the exposure conversion is missing. Camera cuts, resolution changes, incompatible view rectangles, and changes to the representation require history invalidation or a defined resampling path.

The latency tradeoff in numbers. After a step from old value 0 to a constant new value 1, an exponential blend with a=0.1 gives 0.1, 0.19, 0.271, and after ten updates about 0.651. Stable accumulation intentionally remembers the old value. A still screenshot cannot reveal that delay. A camera-motion sequence and a light-change sequence test different causes of history failure.

Short-range occlusion supplies local geometric detail that sparse probes can miss. Ambient occlusion or a bent normal can modify the diffuse and specular reconstruction, but these are additional approximations with explicit ownership. Multiplying every lighting term by an arbitrary AO value can darken direct illumination twice. Match the selected shader path's AO application and show its buffer with the receiver geometry when diagnosing a contact.

Increase the new-sample weight to respond faster. For independent stationary input noise, the steady-state variance ratio is a/(2−a), obtained by solving v = (1−a)²v + a²σ². That assumption excludes correlated samples and changing illumination. The curve models a valid exponential history; Unreal's rejection and fast-update logic deliberately depart from it.

Reflections: sample, trace, and reconstruct glossy transport

Return to C, the polished test sphere. A diffuse probe can tolerate a broad angular reconstruction because the receiver integrates over a hemisphere. The polished sphere asks a much narrower question: what lies near the reflected direction? Low-order SH cannot retain the detailed image of Sponza's columns and balconies. We need a dedicated reflection route.

Classify the receivers before allocating ray work

Read roughness and shading-model data from the primary GBuffer. Classify tiles that require dedicated reflection work, allocate ray records, and generate reflected or microfacet-sampled directions with the information needed to interpret their sampling density. Trace the screen representation first when enabled, then compact unresolved rays into the selected world tracing path. Store hit information and radiance in buffers whose indices map back to the originating pixel or downsampled sample.

Begin with an explicit receiver-to-ray mapping. A tile containing a polished sphere and a rough stone wall may need dedicated rays for only some pixels. The classification mask says which receivers participate; the compacted work list says which records will be dispatched. A downsampled trace grid also needs its selected full-resolution sample offset. Without those mappings, a correct traced radiance can be reconstructed onto the wrong side of the sphere. Clear rejected entries to a declared invalid state before sparse writes, and pass the active count to subsequent indirect dispatches.

In the inspected tile classification shader, NeedRayTracedReflections sets the reflection bit after the material's smooth-bias adjustment. The later list builder turns these flags into indirect work lists. A bit identifies a required kind of work; it is not itself a ray, a hit, or a measured lighting value.

Sample the glossy integral, not a blurred final image

Let \(L_{i,R}\) denote the incident field assigned to the scene-reflection branch after the direct-light ownership split. The target at a receiver is

\[ R(x,\omega_o)=\int f_{\rm spec}(x;\omega_i\!\to\!\omega_o) L_{i,R}(x,\omega_i)\,\max(0,n\cdot\omega_i)\,d\sigma(\omega_i). \]

A perfect mirror selects one direction, but a rough reflector has a distribution of contributing directions. Sampling only the ideal mirror direction and blurring its color afterwards is generally not the same integral: the neighboring rays may hit different columns, see different light sources, or miss into the sky. Use the visible-normal microfacet sampler derived earlier to generate plausible half-vectors, reflect the outgoing direction, and convert the half-vector PDF into a directional PDF. Keep geometric-sidedness rejection and the perfect-specular limit explicit.

\[ \widehat R=\frac1N\sum_{k=1}^{N} \frac{f_{\rm spec}(x;\omega_k\!\to\!\omega_o) \widetilde L_{i,R}(x,\omega_k)\max(0,n\cdot\omega_k)}{p_\omega(\omega_k)}. \]

This is the estimator a minimal reference implementation should make correct. The production implementation can move factors between ray generation, trace payloads, resolve, and final BRDF combination; its intermediate RGB textures are not automatically equal to this final R. It can also bias direction selection, limit ray intensity, downsample, and reuse nearby samples to control cost and variance. Each such choice needs a matching weight or an explicit approximation. A narrower sampling distribution without the corresponding PDF correction changes the brightness as well as the noise.

// Minimal reference contract; production buffer packing and weighting differ.
receiver = decode_primary_interaction(pixel)
(wi, pdf) = sample_specular_direction(receiver, random_sample)
if pdf <= 0 or unsupported_geometric_side(receiver, wi): return invalid
ray = {origin, wi, pixel, pdf, roughness, validity}
hit = trace_scene_representations(ray)
Li = evaluate_owned_incident_field(hit, ray)
sample = specular_bsdf(receiver, wi) * Li * positive_cosine / pdf
store(sample, hit.distance, receiver_geometry, validity)

Now inspect the production storage boundary. Ray generation writes a direction, a signed cone/inverse-PDF field, and a trace distance. The rough branch uses visible-GGX sampling; its inverse-PDF field is clamped, and its sign also carries the first-person flag. Trace throughput is initialized separately to one. This stage does not write the complete BSDF/PDF product in the reference pseudocode. The ordinary sampler also biases one random coordinate by 1 − GGXSamplingBias (default 0.9), without a separate correction for that truncation. That is a deliberate variance/bias choice, so this path should not be presented as an unchanged unbiased microfacet estimator.

Carry unresolved rays across representations

The screen trace and world trace answer the same ray query with different geometric information. Preserve its origin, direction, remaining interval, owner, and accepted-hit state when compacting unresolved work. An uncertain HZB crossing is not permission to sample an unrelated visible pixel, and leaving the screen is not proof of an environment miss. Only the selected continuation route can establish what the available world representation contains along that direction. The tracing chapter supplies the common intersection contract; reflection payloads additionally retain the information needed for hit shading and glossy reconstruction.

A hit distance serves two jobs. It identifies the secondary intersection for shading, and it helps the reconstruction reason about parallax and footprint. A nearby reflected lamp and the distant sky can have similar colors while requiring very different history correspondences. A miss needs its own validity and environment policy, rather than an arbitrary large number indistinguishable from a distant hit. Preserve those states through resolve even when both routes eventually produce RGB.

There is also a second kind of compaction: the compaction modes select misses for continuation, or select hits whose material record requests another lighting pass. “Compacted” therefore does not universally mean “missed.” The queue's predicate and payload must be part of its contract. Screen tracing also consumes a previous SceneColor sample, so its returned color already carries a temporal and shading approximation in addition to screen-space geometry limitations.

Resolve sparse samples without dragging reflections through time

Resolve these sparse samples into a specular signal using geometry, roughness, hit distance, and temporal information. A glossy reflection can have a very different apparent motion from its primary surface; blindly reusing the surface's diffuse history rule can drag a reflection across the object. Distance and roughness inform reconstruction footprints, while disocclusions and mismatched hits must reduce reuse.

To see why, imagine a smooth mirror fixed to the wall while the camera moves sideways. The wall point has one geometric motion correspondence, but the image of a column inside the mirror shifts according to the reflected view. Reprojecting only the wall can therefore find a previous pixel with the wrong reflected column. At a rough surface the response covers a wider angular neighborhood, so reconstruction can tolerate a broader footprint; at a sharp surface that same reuse erases detail. Geometry validation and roughness-dependent weighting are part of the estimator, not a final cosmetic blur.

Build reconstruction in stages. First display independent current samples with validity and hit distance. Then resolve to the output grid using known receiver mappings and compatibility weights. Add history reprojection and explicit rejection, keeping the current estimate available as a fallback. Finally add the selected variance reduction and neighborhood constraints. For each stage, retain whether the signal is raw incident radiance, a partially weighted estimate, or an already reconstructed specular contribution, and convert previous/current pre-exposure consistently. A second base-color or Fresnel multiplication at composition is not a denoising step.

The production resolve makes that distinction concrete. Its sample weight is the microfacet distribution value divided by the stored ray PDF. It applies weights to accepted center and neighbor samples, then divides accumulated lighting by accumulated weight. This is a normalized, partially weighted radiance reconstruction, rather than the complete per-path BSDF estimator above. It still needs the receiver's environment-BRDF factor at composition. The ordinary opaque composition branch blends rough and traced signals and then multiplies by EnvBRDF; clear coat takes a separate layered branch.

Read conditional compilation before describing history rejection. In this version, the proposed normal/roughness lobe-confidence test is disabled by LOBE_CONFIDENCE=0 in the temporal shader. The hit-history plane-depth test is also disabled. Active logic instead uses validity and depth/distance checks, neighborhood clamping, and a choice between surface and reflected-hit histories based on neighborhood error. Roughness still controls accumulation limits, and the separate spatial filter uses a roughness-dependent radius and normal acceptance cone. These are different operations; an inactive temporal lobe test must not be credited with the spatial filter's rejection.

Separate the ray hit from its lighting

At a secondary hit, Surface Cache mode returns a cheap effective diffuse response. Hit-lighting modes evaluate selected material and lighting terms at the actual hit. They can recover directional specular effects that a direction-independent card cannot represent. However, hit lighting is still a real-time estimator with finite tracing, selected source evaluation, and continued cache reuse for some indirect terms. It is not an unbounded recursive path tracer.

Consider a polished sphere reflecting another metallic object. Correct triangle visibility only identifies the second object. If its lighting comes from a fully rough card response, its reflected appearance can still differ from the path tracer. This is the cleanest reason to distinguish the tracing representation from the secondary-shading representation in both code and comparisons.

The hardware trace's completion logic decides whether a hit still requires hit lighting. Successful scene-color reuse can complete a hit; valid radiance-cache coverage can complete a continuation. Sky is added on a remaining miss when enabled, while the optional skylight-leaking term is a separate artistic approximation that can also affect hits. Intensity clamping controls fireflies. None of those operations establishes a fully recursive reference solution. Inspect the reflected signal independently of the material

At C, the captured resolved specular signal is (0.0180664,0.0135498,0.0087891), while the later specular-indirect output is (0.0166016,0.0144043,0.0085449), both view-pre-exposed. The resolved hit depth is 273.75 cm. These values and their distinct versions are retained in the reflection record. Differences between stages reflect reconstruction/history processing; they are not another application of base color to a raw environment sample.

Even the history counter needs its own decode contract. This reflection path stores count/32 in a UNORM target. C's raw byte 96 therefore represents (96/255) × 32 ≈ 12.047 effective accumulated frames, rather than 96 frames. Spatial and temporal interpolation can make that value nonintegral. The screen-probe history uses a different packed format, with four bits for fast-update amount and four for a normalized count. Similar resource names do not imply interchangeable encodings.

Blend overlapping specular estimates instead of adding them twice

For sufficiently rough surfaces, the screen-probe path supplies a rough specular approximation. The dedicated traced-reflection path covers lower roughness. Where their ranges overlap, they estimate overlapping illumination and need a blend. In the ordinary opaque Lumen branch,

\[ \alpha_r=\operatorname{saturate}\left(\frac{r_{\max}-r}{\Delta r}\right),\qquad R=(1-\alpha_r)R_{\rm rough}+\alpha_rR_{\rm traced}. \]

The inspected default post-process threshold is 0.4 with a default fade length of 0.1; the capture manifest records the actual overrides. At roughness 0.2 the ordinary formula gives fully traced weight; at 0.35 it gives half; at 0.5 it gives none. These are workload and reconstruction decisions. They do not imply that a real material suddenly stops reflecting at roughness 0.4. Clear coat, backface-diffuse materials, SSR, water, and translucent front layers have other branches.

A useful experiment changes the tracing cutoff while keeping the spheres' material roughness unchanged. It changes the representation, not the physical scene. A second experiment changes material roughness with the cutoff fixed. That changes the target integral. Keeping these tests separate prevents a quality-setting effect from being explained as a material law.

The analytic direct-light pass already evaluates the material's specular response to its owned lights. A dedicated scene-reflection result must not add those same owned direct connections again. The final composition follows the source partition, lobe partition, and representation blend together.

Assemble one frame and account for every contribution

At this point, the renderer contains several RGB images with very different meanings. Some are primary material data. Some are incoming radiance. Some are irradiance. Some already include a material response. Some use cache pre-exposure and others view pre-exposure. Composition is where an apparently small misunderstanding becomes a systematic lighting error.

For the simplified opaque Default Lit configuration, the remaining diffuse response is \(D^{\rm stored}=e_vE_R/\pi\). Multiply it by the receiver diffuse color. The reflected scene specular signal is chosen or blended according to its route, then receives the corresponding specular response through the composition stage's environment-BRDF factor. Add these to the correctly owned emissive and analytic-direct contributions in the same view-pre-exposed space. The precise production composite also contains occlusion, layered-material, reflection-scaling, and platform branches documented in the reference.

The dependency graph an implementation must schedule

Build scene representations and capture dirty card material pages. Build or update tracing acceleration structures and distance fields. Update selected card direct lighting and radiosity with their intervening final-lighting combines. Rasterize the primary depth/material state and construct the screen hierarchies and visible-light shadow data. Place screen probes, build guides, mark/update demanded world-cache probes, trace and filter incoming lighting, integrate at receivers, and apply valid history. Trace and reconstruct the selected reflection work. Compose the owned lighting contributions and run the display pipeline.

Some of these tasks can overlap. Unreal's render graph handles resource dependencies, and the renderer separates asynchronous gather work from later composition to overlap eligible work with direct lighting. The order in which C++ records passes is not a measurement of GPU execution time. To profile the system, inspect dispatch dimensions, active lists, resource sizes, queue dependencies, and actual GPU timestamps. Summing nested event durations double-counts time, while comparing an instrumented dump frame with an ordinary frame can measure the capture overhead rather than the algorithm.

A practical implementation ladder

Build a correct subset before adding reuse. Begin with rasterized primary surfaces plus exact direct shadow rays and a reference path tracer. Add a single diffuse surface cache with known coordinates; compare its hit response against the reference at the same point. Add virtual pages only after the nonvirtual lookup is correct. Add sparse screen probes on a flat surface, then adaptive placement and geometry-aware interpolation. Add a world cache for far queries, then depth-aware interpolation. Add temporal history last, after a history-free frame is interpretable. Finally add dedicated glossy tracing and the roughness transition. This order leaves a working comparison at each change.

For each persistent resource, answer the same implementation questions: who allocates it, who initializes it, what quantity it stores, how indices map to geometry or directions, which bits indicate validity, which pass writes the current version, which consumers read it, which event invalidates it, and what happens when its budget is exhausted. Omitting one of these can produce an image that looks correct only while the camera is stationary.

The exact engine details are large because these contracts interact, not because the fundamental transport equation keeps changing. A new optimization should state which contract it replaces and what error it introduces. That is the bridge between the ideal path tracer and the engineering system.
