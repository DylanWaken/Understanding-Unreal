# Educational CPU reference path tracer

**This is an original educational CPU renderer, not Unreal Engine, not a Lumen
capture, and not a stand-in for the user's requested identical Unreal scene.**
It exists to make the transport estimators in the Lumen/Veach math chapter
executable on a CPU with no third-party dependencies. The rendered scene is a
Lambertian-only reconstruction of the essay's 4 x 5 x 3 m CPU reference room
(open front, red/green walls, two blocks, ceiling emitter); the PNG carries a
burned-in label saying so, and `manifest.json` repeats the disclaimer.

The implementation is written from scratch for this project. It contains no
copied engine code, no GPU code, and no third-party renderer code.

## Requirements

- CPython 3.9 or newer (final artifact measured on CPython 3.14.6, Windows).
- No `numpy`, no `Pillow`, no compiler, no GPU. Only the Python standard
  library (`math`, `random`, `struct`, `zlib`, `json`, ...).
- A CPU. The reference image takes roughly two to four minutes on one desktop
  core depending on the machine; it is intentionally not a production renderer.

Set `PYTHONDONTWRITEBYTECODE=1` if you do not want `__pycache__` directories.

## Quick start

From the repository root (`UnrealUnderstanding-Math`):

```powershell
# 1. Numerical estimator checks. Writes reference/out/checks.json.
python reference/test_estimators.py --seed 20240601 --samples 200000

# 2. Render the small reference image (raw linear PFM + display PNG +
#    provenance manifest).
python reference/path_tracer.py --width 280 --height 200 --samples 64 `
  --seed 20240601 --exposure 0.6
```

The second command writes:

- `reference/out/reference_linear.pfm` — raw linear radiance, float32 RGB,
  little-endian, PFM bottom-up. No tone curve and no clipping: this is the
  numerical result.
- `reference/out/reference_render.png` — 8-bit sRGB display image, exposure
  applied, with the label "EDUCATIONAL CPU REFERENCE / NOT AN UNREAL CAPTURE"
  and the seed/sample count burned into the pixels. PNG `tEXt` chunks also
  carry the disclaimer.
- `reference/manifest.json` — exact argv, all options, wall-clock timing,
  SHA-256 hashes and byte sizes of the source/README/PFM/PNG/checks, and CPU /
  Python identity.

## Command-line options

```text
--width N            image width (default 280)
--height N           image height (default 200)
--samples N, --spp N samples per pixel (default 48)
--seed N             explicit integer seed (default 20240601)
--max-depth N        maximum surface vertices per path (default 8)
--rr-start N         first path depth where Russian roulette may fire (default 3)
--rr-min F           minimum roulette survival probability (default 0.05)
--exposure F         PNG display exposure only; PFM stays linear (default 0.6)
--out-pfm PATH       linear PFM output path
--out-png PATH       display PNG output path
--manifest PATH      provenance JSON output path
--quiet              suppress row progress
```

Determinism: each pixel gets its own `random.Random` stream derived from
`(seed, x, y)`, and primary samples are jittered inside the pixel (stratified
in x). Re-running the same command reproduces byte-identical PFM and PNG files;
only the timing fields in the manifest change. Different seeds give different
noise realizations.

## What the renderer implements

### Scene and camera

- CPU-lab reconstruction of the essay's room, in metres with `z` up:
  `x in [-2, 2]`, `y in [0, 5]`, `z in [0, 3]`.
- Red wall at `x = -2`, green wall at `x = +2`, neutral floor at `z = 0`,
  ceiling at `z = 3`, back wall at `y = 5`. The front at `y = 0` is open to a
  black environment.
- One 1.3 m x 1.2 m ceiling emitter at `(0, 2.7, 2.98)`, radiance
  `(16, 14, 11)` in arbitrary linear units, emitting downward only.
- A short matte block on the left (`x` in `[-1.25, -0.30]`, `y` in
  `[2.3, 3.4]`, height 1.05 m) and the essay's tall right block placement
  (`x` in `[0.30, 1.20]`, `y` in `[3.3, 4.3]`, height 1.80 m).
- All geometry is rectangles; boxes are six rectangles behind an AABB test.
- Pinhole camera at `(0, -4, 1.65)` looking at `(0, 2.8, 1.4)`, 43 degree
  vertical field of view, aspect 1.4 (the artifact is 280 x 200; the essay's
  reference image is 560 x 400). Camera rays are generated by `camera_ray`.
- **The tall right block is not glossy here.** Unreal gives it metallic 0.85 /
  roughness 0.12; this renderer has no microfacet lobe and uses a neutral
  Lambertian albedo instead. The manifest says so explicitly.

The room, camera and block placements are aligned with the essay's CPU lab so
the geometry is recognizable. The image is still an independent educational
CPU render, not an Unreal scene or capture.

### Lambertian BSDF sampling

The only BSDF is Lambertian with albedo `rho`:

```text
f_r = rho / pi
p(omega) = cos(theta) / pi              (cosine-weighted hemisphere)
throughput *= f_r cos(theta) / p = rho
```

`cosine_sample` builds an orthonormal basis around the shading normal and
samples `p(omega)` exactly; it returns both the direction and its pdf so the
same pdf can be used by MIS.

### Next-event estimation and the area Jacobian

At every non-emissive diffuse vertex the renderer samples one light uniformly
by area. With `p_A = 1 / (area * n_lights)`:

```text
dA = (d^2 / cos_light) dOmega
p_omega = p_A d^2 / cos_light
L_o += throughput * (rho/pi) * L_e * cos_x / p_omega * w_light
```

where `cos_x` is at the receiver and `cos_light` is at the emitter. The
resulting estimator is the usual `rho/pi * L_e * cos_x * cos_light / (p_A d^2)`
(up to the MIS weight). A shadow ray from the receiver to the sampled emitter
point tests occlusion. It excludes only the target emitter endpoint, not every
emissive surface: another emitter between receiver and target is opaque
geometry and must block. The area-to-solid-angle conversion lives in
`area_to_solid_angle_pdf` so the tests can exercise it directly.

At the final path vertex no continuing surface path is traced. NEE there is used
with weight 1 rather than the MIS light weight, because the competing
BSDF-sampled emitter strategy does not exist. This terminal-depth rule is
covered by `terminal_depth_nee_not_mis_weighted`.

If the API's environment is nonblack, a separate cosine-sampled ray estimates
its direct contribution at this terminal vertex. Only an environment miss
contributes; area-emitter hits are already represented by the unweighted NEE
estimate, and further surface scattering is truncated. Thus the cap retains
direct environment lighting as well as direct area-emitter lighting. The
default rendered scene has a black environment and does not enter this branch.

### Power-heuristic MIS

Both strategies are evaluated on every path: light sampling (NEE) and
BSDF sampling that may hit an emitter.

```text
w_light = p_light^2 / (p_light^2 + p_bsdf^2)
w_bsdf  = p_bsdf^2  / (p_light^2 + p_bsdf^2)
w_light + w_bsdf = 1
```

The NEE contribution is weighted by `w_light`; a BSDF-sampled emitter hit is
weighted by `w_bsdf`. Except at the terminal vertex (where only NEE exists),
both strategies are evaluated and the estimator is their sum (there is no 1/2
strategy-selection factor). The light-sampling pdf includes the uniform
light-selection pmf `1/n_lights`, and the BSDF pdf is `cos_x/pi`. Emitters
terminate paths: they are not reflective, so no emission can be counted twice.

### Russian roulette

After the BSDF update, for `depth >= rr_start`, survival probability is

```text
q = max(rr_min, min(0.95, max(throughput)))
```

with probability `q` the path continues and throughput is divided by `q`;
otherwise it terminates. This is the standard weight-compensated roulette and
is unbiased in expectation. The finite `--max-depth` is a separate truncation
bias: the renderer does not claim to integrate infinite interreflection.

### Output and display

- PFM is raw linear float32 RGB, bottom-up, little-endian (`-1.0` scale).
- PNG is written with `zlib`/`struct` directly; no Pillow. Display value is
  `clip(radiance * exposure, 0, 1)` converted with the sRGB transfer function.
- The PNG label and tEXt metadata are part of the artifact, not a later
  annotation; the manifest hashes the exact bytes that were written.

## Numerical checks

`test_estimators.py` is deterministic and prints a `[PASS]`/`[FAIL]` line for
each check plus `reference/out/checks.json` with every measured value, seed and
tolerance:

1. **Cosine pdf / Lambertian constant environment.**
   For a tilted normal, verifies `|d| = 1`, `d . n >= 0`, and
   `pdf = cos/pi`, so `E[cos/pdf] = pi` exactly. A separate uniform-hemisphere
   MC estimate checks `integral pdf dOmega = 1`. The path tracer is then run on
   a Lambertian plane under a constant environment `L_env` with
   `max_depth = 2`; the expected result is exactly `rho * L_env`.
2. **Area/solid-angle Jacobian.**
   Deterministically integrates `p_omega dOmega` over the rectangle using
   `dOmega = cos_light/d^2 dA`; the result must be 1. A Gauss-Legendre
   quadrature of the projected solid angle is computed at orders 12, 32 and 64
   to show the reference has converged.
3. **MIS partition.**
   Checks `w_light + w_bsdf = 1` for 50k random positive pdf pairs, and
   compares the sum of the NEE and BSDF MIS components against a deterministic
   Gauss-Legendre reference for a finite rectangle above a Lambertian point.
   The Gauss-Legendre reference is the "known finite bound" for direct
   lighting; the MC tolerance is four standard errors.
4. **Russian roulette expectation.**
   Simulates the compensated geometric series (`a = 0.6`, `q = 0.8`, depth
   0..40) whose exact finite-horizon expectation is
   `sum_{k=0}^{40} a^k = 2.499999998`. The measured mean is compared with
   `4 * SE`. An uncompensated control is also reported; it must sit near the
   biased value `sum (a q)^k = 1.923077`, demonstrating that the check detects
   a missing compensation factor. The tracer's actual RR branch is exercised
   separately on the constant-environment plane with `rr_start = 0`, where
   `q = 0.6` and compensation must preserve `E[L] = 1.2`; that mean is checked
   against `4 * SE` as well.
5. **Emitter double-counting guard.**
   A camera ray that hits an emitter directly must return exactly the emitter
   radiance, with no NEE or MIS contribution.
6. **Camera basis and orientation.**
   The center ray equals the forward direction, screen-right rays have a
   positive dot with the right basis, screen-left rays negative, up/down
   behave likewise, adjacent pixels differ, and the red wall lands on screen
   left while the green wall lands on screen right (no mirrored image).
7. **Terminal-depth NEE.**
   A `max_depth = 1` scene has only NEE at its sole vertex. The measured direct
   radiance must match the deterministic reference; MIS-weighting that vertex
   against an untraced BSDF strategy would bias it low.
8. **Target-only shadow exclusion.**
   A second emissive rectangle placed between receiver and target must block
   the shadow ray; only the target emitter is excluded.
9. **Terminal-depth environment.**
   At `max_depth = 1`, a Lambertian plane under a nonblack constant environment
   must still return `rho * L_env`; the terminal path must not silently delete
   this source class while retaining direct area lights.

The checks are not a proof of the renderer; they are executable evidence that
the specific formulas used here are consistent. See
`reports/reference-report.md` for the measured run, seed and tolerances.

## Limitations and scope

- Diffuse Lambertian transport only; no specular, glass, participating media,
  textures, spectral rendering, or photon mapping. In particular the essay's
  tall right block is glossy/metallic in Unreal and Lambertian here.
- RGB transport in arbitrary linear units; no claim of radiometric calibration.
- Finite `--max-depth` means the result is biased relative to infinite
  interreflection; this is stated explicitly rather than hidden.
- The room dimensions, camera and block placements are aligned with the essay's
  CPU lab, but the image is not an Unreal scene, not a capture, and does not
  claim the Unreal glossy BRDF, lighting units, exposure or Lumen caches. It
  must not be presented as an identical Unreal render.
- Rendering is single-threaded CPython. No GPU work is performed.
