# VSM light/shadow facts (pinned)

Engine `D:/UnrealEngine` @ `71fe36aac5a8df5ccd66c763ffc902b29b6a9c43` (base). 47 anchors in `notes/anchors.json`; each hash is SHA-256 of the cited UTF-8 lines joined with LF, no trailing LF. All 20 cited files are clean vs `HEAD` (`git diff --quiet`). Static source reading only; no GPU run. `[D]` = direct source fact, `[I]` = inference from those facts.

1. **Directional VSM = per-primary-view ortho clipmap stack.** `[D]` Each directional light gets a `FVirtualShadowMapClipmap` built from that view's matrices and viewport size [d11]; its `WorldOrigin` is the camera view origin [d03]. Light orientation is `FInverseRotationMatrix(LightDirection.Rotation()) * FaceMatrix` [d01], and each level's shadow view is that rotation at the level center with the level's ortho projection [d07].

2. **Clipmap geometry and depth range.** `[D]` Level radius is `2^(level+1)` [d08]. Each level uses half-extent `2*RawLevelRadius`, snaps its center to the level-radius grid [d04,d05], and sets `ViewToClip = FReversedZOrthoMatrix(HalfLevelDim, HalfLevelDim, 0.5/ViewRadiusZ, ViewRadiusZ + ViewCenterDeltaZ)` [d06] (square ortho volume, reversed-Z). Cached levels keep the original `ViewCenterZ/ViewRadiusZ`; a moved camera reuses pages by a page-space offset [d27].

3. **Which clip level, and why directional is unbounded.** `[D]` Page marking picks the clip level from `log2(distance to clipmap origin)` [d10], then floors it [d09]. Resolution scale is derived from the camera projection scale and viewport width (`LodScale = 0.5/ProjectionScale.X * VirtualMaxResolutionXY / viewportWidth`) [d02]. So the clip index is chosen by world distance-to-origin, while the level scale is chosen so a camera pixel maps to roughly one shadow texel. Directional lights have no distance attenuation, so the clipmap follows the camera instead of having a light-radius cutoff.

4. **Point lights: six 90-degree perspective faces.** `[D]` The point initializer sets a sphere subject bound, `MinLightW=0.1`, `MaxDistanceToCastInLightW=Radius`, and `bOnePassPointLightShadow=true` [d16]. Setup builds six cube faces with hard-coded face/up vectors; `OnePassShadowFaceProjectionMatrix = FReversedZPerspectiveMatrix(PI/4, 1, 1, 1, Radius)`, i.e. 90-degree FOV, near 1, far = light radius [d14]. Non-spot local page marking selects the cube face by direction [d31].

5. **Spot lights: one map, cone projection.** `[D]` The spot initializer uses the cone bounding sphere, `Scales=(InvTanOuterCone, InvTanOuterCone)`, and far distance = light radius [d17]. `ViewToClip = scale * FShadowProjectionMatrix(MinSubjectZ, MaxSubjectZ, WAxis)` [d13]. That matrix's W row varies with Z, so it is a perspective cone (not an ortho box) [d15].

6. **Rect lights: a point cube from the rect center, area only in soft-source sampling.** `[D]` The rect initializer is the same shape as the point initializer: sphere subject bound, one-pass cube, far = radius; it does not use `SourceWidth`/`SourceHeight` [d18]. `FRectLightSceneProxy` derives from `FLocalLightSceneProxy` and does not override `GetSourceRadius` [d46], so the base returns 0 [d20] and VSM projection data copies that 0 [d21]. The rect's shader params carry `SourceRadius=SourceWidth*0.5` and `SourceLength=SourceHeight*0.5` [d19]. Local SMRT ray generation samples a disk of `Light.SourceRadius` around the light direction [d44]; the VSM shader tree has no reference to `SourceLength` (search of `Engine/Shaders/Private/VirtualShadowMaps`: 0 hits). Net: rect shadow depth is a six-face cube from the rect center, with a circular half-width soft source; not the actual rectangle, and not many independent lights. `[I]` Rect height is absent from VSM shadow rays.

7. **Rect/local shadow alternative path.** `[D]` The local VSM branch is taken only when the initializer is not `bRayTracedDistanceField`; otherwise the local light falls through to the classic/RTDF shadow setup [d22,d47]. So rect VSM and ray-traced rect shadows are different implementations, not two modes of the same projection.

8. **Raster pipeline and layer merge.** `[D]` Casters are transformed by the light view/clip matrices [d12,d23]; the non-Nanite VSM pixel shader decodes the page table and writes `InterlockedMax(OutDepthBufferArray[uint3(pAddress, ArrayIndex)], asuint(DeviceZ))` [d23]. With reversed-Z this max keeps the nearest occluder. `ArrayIndex = bStaticPage ? StaticArrayIndex : 0` [d23]; the static cache layer is array slice 1 when caching is enabled [d36]. Per-page draw commands carry the static-page bit [d39]. Static-dirty pages are merged into the dynamic slice with `max(slice0, staticSlice)` [d37], dispatched only for selected static-dirty pages [d38].

9. **Receivers mark pages; marking is screen-depth driven.** `[D]` Directional marking runs for every directional VSM using primary scene depth, plus optional water depth and front-layer translucency depth [d32]. Local marking reads the culled light grid at the visible pixel's depth, tests inverse radius, spot cone, and the rect "behind light" test, then calls `MarkPageLocal`; non-spot lights pick a cube face by receiver-to-light direction [d33,d31]. `MarkPage` projects the receiver into shadow UV, rejects it outside the light clip, computes the virtual address for the supplied mip, and marks `ALLOCATED | DETAIL_GEOMETRY | PRIMARY_REQUEST` (plus an optional receiver mask) [d30].

10. **Caster culling and off-screen occluders.** `[D]` For local VSM the culling volume is the light proxy bounding sphere plus a light-space `CasterOuterFrustum` [d24]; point cube frustum planes sit at the light radius [d14]; caster interaction range is `MaxDistanceToCastInLightW=Radius` [d16,d17]; invalidation also distance-culls instances by `LightRadius + InstanceRadius` [d29], with the cached light's `AffectsBounds` origin/radius test [d26]. That volume has no primary-camera plane. `[I]` Therefore casters outside/behind the camera still render into any requested page if they are inside the light volume and overlap that page. Directional clipmap culling is deliberately conservative and often effectively no culling [d45].

11. **Cache keys and invalidation.** `[D]` Clipmap key = `{LightDirection, FirstLevel}`; local key = `{WorldToLight, PreShadowTranslation, bIsDistantLight}` [d25]. A key change sets `RenderedFrameNumber=-1`; the next frame is rendered uncached, then it can re-cache [d28]. Camera translation is not in the key: while the Z radius is unchanged, cached levels keep pages via `PageAddressOffset` while `|DeltaZ| + LevelRadius <= 0.9*ViewRadiusZ`, otherwise the level is invalidated [d27]. Light rotation changes the clipmap key and invalidates the clipmap [d25,d28]. Moving/deformable/revealed casters enqueue instance invalidations [d40]; invalidation box-culls the instance into light-clip pages and ORs invalidate flags only into overlapped allocated pages, not the whole map [d29].

12. **Unresolved risk (static reading, not reproduced).** `[I]` The local cache key does not contain the spot outer-cone angle or initializer `Scales` [d25], while local projection matrices are re-uploaded only when `IsInvalidated()` [d41,d43]. A pure spot cone-angle change (no position/rotation change) can therefore leave a stale `ShadowViewToClipMatrix`/cached projection until another key component changes or another system invalidates the light proxy. Source radius itself is refreshed every frame [d21] and does not affect VSM depth. This needs a dynamic check before making article claims.

13. **Off-screen taxonomy (light / occluder / receiver).** `[D]` Receiver demand is screen-space: pages are marked only from visible depth (and optional water/translucency depth), not from arbitrary off-screen receivers [d32,d33]. Coarse pages exist specifically for systems that need data outside the per-pixel marks: directional coarse clip-level pages for volumetric fog and translucent light volume [d34], and a last-mip page for local coarse/single-page lights [d35,d42]. `[I]` An off-screen light source whose radius reaches visible pixels still gets pages because its light-grid entry is read at those visible pixels [d33]; an off-screen occluder still casts because culling is light-space and page-based [d24,d29]; an off-screen receiver gets no pages except the coarse-page cases. No Lumen/card receiver input appears in the page-marking file, so `[I]` off-screen Lumen surface cache/cards do not create VSM page demand through this path.

## Plan drift / corrections

- Plan wording "rect source actual VSM projection/source extent" is not supported: rect VSM uses a point-style six-face cube from the center [d18], with a disk of half the width as the soft-source approximation [d19,d44], not a rectangular area projection.
- Plan wording "distance lights no attenuation" applies to directional lights only; point/spot/rect VSM are radius-bounded (far plane = light radius) [d16,d17,d18].
- Plan's screen-space caution is correct for receivers but not for casters: page demand is screen-derived [d32,d33], while caster eligibility is light-space [d24,d29].
